## Root cause

The preceding pipeline fixed native head pixels and upright height, then permitted a separately drawn torso. Axe DOWN ready was 51×55 opaque source pixels; accepted Greatsword DOWN ready was 41×55. Both passed the same height limit. Weapon-inclusive bounds and the palette-based armor-width heuristic are also unsuitable as the sole anatomy gate. Different arm positions can legitimately change silhouette width; the complete approved pose is the reference.

## Required workflow for every new weapon

1. Read this guide and use the [complete reference board](../../art_source/reference/characters/king/body_library_v1/turnaround_and_walk.png), isolated ready PNGs, and runtime body library. The previous `native_identity_v1` remains historical head provenance, not the sole body-size authority.
2. Reuse canonical standing/walking bodies. Change weapon texture, actual palm/mount anchors, painter order and independent effects. A different blade length never changes actor scale, body origin or anatomy pixels.
3. For a new attack, reference the complete turnaround and approved action family at identical nearest-neighbor zoom. Review torso/head/limbs, real grips, source gutters, anticipation/contact/recovery and next-cut continuity together. A genuinely new body pose needs explicit full-body visual review and a separate versioned pose; never stamp a head onto an unreviewed torso and treat the result as accepted.
4. Run the immutable library/candidate gate and stock regression gate before selecting resources. Render the real Player through equips, travel, blocked travel, attacks, released recovery, AFK/rest retrieval and the normal Bag. Preserve accepted Greatsword source hashes.

Offline checks use the installed Godot console with `--path .`:

```powershell
& 'D:/WORK_APP/godot/Godot_v4.7-stable_win64_console.exe' --headless --path . --script res://tools/check_king_body.gd --quit-after 2
& 'D:/WORK_APP/godot/Godot_v4.7-stable_win64_console.exe' --headless --path . --script res://tools/check_king_body.gd --quit-after 2 -- --candidate=res://assets/characters/playable/king/body_library/v1/down_run_body.png --pose=down_run
& 'D:/WORK_APP/godot/Godot_v4.7-stable_win64_console.exe' --headless --path . --script res://tests/king_shared_body_smoke.gd --quit-after 2
```

`check_king_body.gd` rejects a candidate with different dimensions or opaque pixels, including a wider torso of unchanged height. It is a reuse gate, not a validator for arbitrary new motion. The stock regression separately checks every family gait, Sword body texels/mirror/nonlocomotion preservation, axe ready/recovery and immutable references. `tests/king_down_body_polish_smoke.gd` checks every DOWN body/mask against its complete source plus the explicit offset, matching palms/head/sole/phase metadata, exact continuation endpoints and1041 preserved pre-change files. Never loosen the gate to fit a candidate.

## Rebuild and play

`tools/build_king_shared_bodies.gd` is offline only. It reads the verified original pre-change archive and frozen bodies; it writes sibling assets and the two stock family selections, including the final DOWN registration layer. It refuses changed frozen body hashes. Unchanged family selectors are not rewritten; changed selectors use a temporary file and replacement with explicit error handling. Run it headless, import the PNGs, then run the checks. New PNG imports use nearest, lossless compression, no mipmaps and no alpha-border expansion. The original axe/dual builders reproduce historical assets; they no longer select the current shared standing/gait/registered attack roots. Do not rerun them against stock without restoring this final shared-body layer and verifying all checks.
